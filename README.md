# LesOS

**LesOS** — минималистичная операционная система на ассемблере и C++, загружаемая с дискеты (1.44 МБ). Демонстрирует базовые концепции ОС: загрузку в защищенный режим, управление памятью и простой текстовый интерфейс.

## Возможности

- 🔧 **Загрузчик** (512 байт): переход из 16-битного в 32-битный режим, загрузка ядра с диска
- ⌨️ **Простой shell**: интерпретация нажатий клавиш и вывод на экран
- 🖥️ **VGA текстовый режим**: прямой вывод в видеопамять (0xB8000)
- 🔌 **Serial I/O**: вывод на последовательный порт для отладки

## Архитектура

| Файл | Назначение |
|------|-----------|
| `boot.asm` | Загрузчик: чтение ядра с дискеты, переход в защищённый режим |
| `kernel.cpp` | Ядро: обработчик клавиатуры, текстовый интерфейс, serial/VGA вывод |
| `kernel.ld` | Скрипт линкера, позиционирует ядро по адресу 0x10000 |
| `Makefile` | Сборка образа диска |

### Поток выполнения

1. **Boot** (`boot.asm`): BIOS загружает 512-байтовый сектор по адресу `0x7C00`
2. Загрузчик читает 32 сектора ядра (16 КБ max) с дискеты в память по адресу `0x10000`
3. Переключение в 32-битный защищённый режим через GDT
4. **Kernel** (`kernel.cpp`): инициализация serial/VGA, очистка экрана, вывод prompt `lesOS> `
5. Бесконечный цикл опроса порта клавиатуры `0x60`
6. Текст выводится одновременно на VGA-экран и в serial-порт

## Требования

- `nasm` — ассемблер для boot-сектора
- `g++ -m32` — 32-битный компилятор C++ (на 64-битной системе нужен `g++-multilib`)
- `binutils` — `ld` и `objcopy`
- `qemu-system-i386` — эмулятор для запуска
- `make` — сборка проекта

## Быстрый старт

```bash
# Сборка образа диска
make

# Запуск в эмуляторе
make run

# Очистка артефактов
make clean
```

После запуска ты увидишь prompt `lesOS> ` — введи текст на клавиатуре. Текст одновременно появляется на экране и отправляется в serial-порт (доступно в логе QEMU с `-serial stdio`).

### Запуск на Windows

Сборка рассчитана на Unix-окружение (`dd`, `wc`, `sh`). Используй WSL2:

```bash
wsl
sudo apt install nasm g++-multilib binutils qemu-system-x86 make
```

Для отладочного вывода замени в `Makefile` флаг `-serial null` на `-serial stdio`.

## Сборка для реальной дискеты

Если есть старый дисковод:

```bash
# После make
sudo dd if=lesos.img of=/dev/fd0 bs=512
```

## Ограничения

- ⚠️ Ядро максимум 16 КБ (проверка в `Makefile`, ограничение загрузчика — 32 сектора)
- ⚠️ Только дискета 1.44 МБ (другие носители не поддерживаются)
- ⚠️ Только текстовый интерфейс (нет файловой системы, многозадачности и сети)
- ⚠️ Работает только на x86-32
- ⚠️ Нет IDT — клавиатура опрашивается напрямую через порт `0x60`, поэтому Shift и Caps Lock не переключают регистр

## Стратегия развития: два пути

Начиная с файловой системы, проект упирается в объём работ. Реализовать сопоставимое с Linux поведение с нуля — это годы. Есть два принципиально разных маршрута.

### Путь A. Продолжить с нуля

**Что это:** собственное ядро, которое мы пишем сами.

**Плюсы**

- Полный контроль и понимание каждой строки
- Никаких внешних зависимостей и лицензий
- Чистое понимание того, как устроены GDT, paging, прерывания, ФС
- Проект остаётся учебным стендом, а не форком

**Минусы**

- Огромный объём: драйверы, планировщик, ФС, сеть
- Реалистичный потолок — «ОС для демонстрации», а не рабочая система
- Нельзя запустить браузер, аудио, нормальный софт
- Отладка каждого нетривиального механизма с нуля

**Реалистичная цель:** ОС, которая загружается с дискеты, умеет FAT12, `ls -la`/`cd`/`cat`, многозадачность и работает в QEMU.

### Путь B. Взять ядро Linux и кастомизировать

**Что это:** не своё ядро, а собственная сборка и дистрибутив на базе Linux.

**Плюсы**

- Работающая файловая система, сеть, USB, многозадачность «из коробки»
- Можно добавить init-систему, шелл, собственный `ls -la`
- Реальное применение: свой дистрибутив для сервера, встраиваемых устройств, студии
- Современные возможности: cgroups, namespaces, systemd, контейнеры

**Минусы**

- Это уже **не** минималистичная ОС — Linux занимает ~10–30 МБ и требует boot protocol EFI/BIOS
- Нужно разобраться в Kconfig, `make menuconfig`, модулях ядра, initramfs
- Основная работа смещается с написания кода на конфигурацию и упаковку
- Теряется учебный смысл оригинального проекта
- Нужно соблюдать лицензию GPL-2.0

**Реалистичная цель:** минимальный дистрибутив (например, на базе BusyBox + custom init) либо кастомное ядро Linux с включёнными драйверами.

### Сравнение

| Критерий | Путь A: с нуля | Путь B: на базе Linux |
|----------|:--------------:|:--------------------:|
| Время до `ls -la` | месяцы | дни |
| Понимание основ ОС | полное | поверхностное |
| Пригодность как учебный проект | высокая | низкая |
| Реальная рабочая система | нет | да |
| Объём кода, который пишем сами | ~10–20 тыс. строк | десятки строк конфигурации |
| Зависимость от внешнего кода | нет | полная |
| Размер образа | 1.44 МБ дискета | десятки МБ |
| Лицензия | своя | GPL-2.0 |

### Рекомендация

**Разделять проекты, а не смешивать.**

- **LesOS** оставить учебным: путь A, цель — `ls -la`, `cd`, `cat`, FAT12, многозадачность. Это то, что реально интересно писать с нуля и чему реально можно научиться.
- **Отдельный репозиторий** завести под путь B, когда упрётеся в ограничения собственного ядра. Например, `lesos-distro` — BusyBox + собственный init + утилиты.

Попытка сделать оба направления в одном репозитории приведёт к тому, что учебный проект раздуется инфраструктурой дистрибутива и потеряет фокус.
