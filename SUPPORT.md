# Поддержка проекта LesOS

LesOS — учебный проект, и «поддержка» здесь означает сообщество, документацию и помощь новичкам, а не гарантии продакшн-сервиса.

---

## 1. Где искать ответ

| Канал | Когда использовать |
|-------|-------------------|
| [Issues](https://github.com/Musi596/LesOS/issues) | Ошибки сборки, регрессии, вопросы по функциональности |
| [Discussions](https://github.com/Musi596/LesOS/discussions) | Общие вопросы, идеи, обсуждение архитектуры |
| [CONTRIBUTING.md](CONTRIBUTING.md) | Процесс внесения изменений, ревью, стиль кода |
| [SECURITY.md](SECURITY.md) | Уязвимости и проблемы безопасности |

GitHub Issues проекта — единственный официальный канал. Автор не ведёт Telegram, Discord или email-поддержку.

## 2. Перед созданием Issue

Убедитесь, что:

1. Вопрос не задавался ранее — воспользуйтесь поиском по Issues.
2. Issue описывает **реальную проблему**, а не общий вопрос (для общих вопросов — Discussions).
3. Приведены шаги для воспроизведения.
4. Указана версия/коммит и окружение (ОС, версия QEMU, версия компилятора).
5. Код и логи оформлены в блоках `code` и `text`.

**Шаблон Issue:**

```markdown
### Описание
Что произошло.

### Шаги для воспроизведения
1. `make`
2. `make run`
3. ...

### Ожидаемое поведение
Что должно было случиться.

### Фактическое поведение
Что случилось на самом деле.

### Окружение
- ОС: Ubuntu 24.04
- g++: 12.3.0
- nasm: 2.16.03
- qemu-system-i386: 8.2.0

### Логи
```
qemu: lesOS: kernel read failed
```
```

## 3. Частые проблемы

### `make` падает: `nasm: command not found`

Не установлен ассемблер:

```bash
sudo apt install nasm
```

### `g++` падает: `fatal error: bits/c++config.h: No such file or directory`

Нет 32-битных заголовков. Добавьте multilib:

```bash
sudo apt install g++-multilib
```

### `collect2: ld returned 1 exit status` / `cannot find crt0.o`

Системная libc в 32-битном режиме не установлена:

```bash
sudo apt install gcc-multilib libc6-dev-i386
```

### `Kernel exceeds 16 KiB boot limit`

Загрузчик читает только 32 сектора (16 КБ). Уменьшите код, вынесите строки в `.rodata` или увеличьте число читаемых секторов в `boot.asm` (константа `sectors_left`) и размер образа в `Makefile`.

### `Kernel exceeds 16 KiB boot limit` на Windows

Проверка размера в `Makefile` использует `wc`/`dd` из Unix-окружения. Используйте WSL, MSYS2 или Cygwin.

### На экране `lesOS: kernel read failed`

Загрузчик не смог прочитать ядро с дискеты. Проверьте:

- образ действительно 1.44 МБ: `ls -l lesos.img` → 1474560 байт;
- `boot.bin` ровно 512 байт и заканчивается сигнатурой `0x55 0xAA`;
- дискета не повреждена (при записи на реальную — попробуйте другой дисковод).

### Экран остаётся пустым / нет реакции на клавиши

- Ядро опрашивает порт `0x60` напрямую, без установки IDT и обработчика прерываний — это ожидаемое поведение, а не баг.
- В QEMU откройте терминал: `QEMU 0x60` клавиши работают, но Shift/Caps Lock не переключают регистр (нет обработки скан-кодов-модификаторов).
- Проверьте размер `kernel.bin`: он не должен превышать 16 КБ.

### В QEMU ничего не видно

Проверьте параметры запуска:

```bash
qemu-system-i386 -boot order=a -display gtk -vga std \
  -serial stdio -monitor none \
  -drive format=raw,file=lesos.img,if=floppy
```

В `Makefile` стоит `-serial null` — чтобы увидеть отладочный вывод, замените на `-serial stdio`.

### Сборка из-под Windows

Сборка предполагает Unix-окружение (`dd`, `wc`, `sh`). Используйте WSL2:

```bash
wsl  # внутри дистрибутива
sudo apt install nasm g++-multilib qemu-system-x86 make
```

## 4. Что НЕ поддерживается

Проект осознанно ограничен и не будет получать:

- загрузку с HDD, USB, CD, сетевой карты (PXE);
- 64-битный режим (long mode);
- страничную память, виртуальную память, защиту страниц;
- файловую систему (FAT12/NTFS);
- многозадачность и планировщик;
- сетевой стек;
- USB, звук, графический режим;
- поддержку дискет 720K/1.2M/2.88M.

Просьбы по этим пунктам оформляйте как идеи в Discussions, а не как баги.

## 5. Сроки ответа

Явных SLA нет. Ориентировочно:

- Триаж Issues — несколько дней;
- Ревью Pull Request — от нескольких дней до пары недель;
- Ответ на security-репорт — см. [SECURITY.md](SECURITY.md).

Если Issue не отвечают более двух недель, это не повод создавать дубль. Попробуйте написать в Discussions.

## 6. Коммерческая и кастомная поддержка

Автор проекта не оказывает платной, гарантированной или SLA-поддержки. Любые заявления о поддержке от третьих лиц не имеют отношения к проекту.
