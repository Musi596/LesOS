# Политика безопасности (Security Policy)

## Supported Versions

LesOS — учебная операционная система. Поддерживаются только последние изменения в основной ветке (`master`).

| Версия | Поддерживается | Получает обновления безопасности |
|---------|:-------------:|:-------------------------------:|
| `master` (актуальная) | ✅ | ✅ |
| Предыдущие коммиты / форки | ❌ | ❌ |
| Устаревшие теги | ❌ | ❌ |

Политика обратной совместимости не применяется: проект не проходит семантическое версионирование.

---

## Область действия

### Входит в область

- Реальные уязвимости, позволяющие получить произвольный код или повлиять на целостность/доступность системы.
- Ошибки в загрузчике (`boot.asm`), приводящие к загрузке некорректного образа, переполнению буферов или некорректной инициализации памяти.
- Дефекты скрипта линковки (`kernel.ld`), из-за которых секции попадают за границу загруженного образа.
- Несанкционированный доступ к памяти ядра из пользовательского (внешнего) ввода: клавиатура, COM-порт, дискета.
- Ошибки в `Makefile` / CI, из-за которых в релиз попадает некорректно собранный образ.

### Не входит в область

- Ограничения архитектуры, являющиеся дизайном проекта (см. ниже).
- Уязвимости, существующие только в QEMU, BIOS, эмуляторе или сторонних зависимостях.
- Отсутствие криптографии, TLS, сети — их нет by design.
- Проблемы сборки, вызванные отсутствием зависимостей у пользователя.
- DoS, воспроизводимый только в отладочном режиме QEMU (`-d` флаги).
- Отсутствие `CR0.WP`, очистки `a20`, `PIC`/`PIT` и других механизмов, — как «архитектурные упрощения».

## Известные архитектурные ограничения

Ядро намеренно минимально. Перечисленное ниже — не уязвимости, а сознательные упрощения, документированные в [README.md](README.md):

- нет IDT и таблицы векторов прерываний — используется опрос порта `0x60`;
- нет страничной памяти и колец защиты — весь код работает в `ring 0`;
- нет изоляции пользовательского и системного режима;
- нет проверки целостности образа ядра (нет подписей, нет Secure Boot);
- загрузчик жёстко доверяет геометрии дискеты 1.44 МБ и всегда читает 32 сектора;
- нет защиты от переполнения `cursor` за пределы `80×25` в сценариях непрерывного ввода без переноса (обрабатывается сбросом экрана, но не проверкой границ строки).

## Сообщение об уязвимости

Не создавайте публичный Issue. Используйте приватный канал:

**GitHub Security Advisories**
→ https://github.com/Musi596/LesOS/security/advisories/new
→ кнопка «Report a vulnerability»

Если функция недоступна, отправьте сообщение мейнтейнеру через форму «Report a vulnerability» на странице репозитория.

**Не используйте** для этого Issues, Pull Requests, Discussions или публичные комментарии.

### Что указать в отчёте

1. Тип: CWE-классификация (например, CWE-787, CWE-119, CWE-798).
2. Затронутые файлы и строки.
3. Условия воспроизведения (ОС, версия QEMU, параметры запуска, содержимое дискеты).
4. Шаги воспроизведения или минимальный код.
5. Влияние: что получает атакующий и при каких предпосылках.
6. Предложенное смягчение, если есть.

### Что указать, если уязвимость «очевидна из архитектуры»

Опишите сценарий эксплуатации, а не отсутствие контроля. Формулировка «нет MMU» не уязвимость; формулировка «пользовательский ввод через клавиатуру перезаписывает VGA-буфер за пределами 2000 символов» — уязвимость.

## Сроки ответа и раскрытия

| Этап | Срок |
|------|------|
| Подтверждение получения | до 7 дней |
| Первичная оценка серьёзности | до 14 дней |
| Исправление критичной/высокой проблемы | по возможности, целевой срок 30 дней |

Ожидаемый канал раскрытия: обсуждение в приватном Advisory, фикс в ветке, запись в описании Advisory, публичное упоминание — по желанию автора отчёта.

Публичного CVE не выдаётся, если уязвимость относится к ограничениям дизайна или требует физического доступа к машине в недоверенной среде.

## Проверка образов

Образы LesOS не подписываются. Сборка воспроизводима из исходников:

```bash
git clone https://github.com/Musi596/LesOS.git
cd LesOS
make                      # требует nasm, g++ -m32, binutils
sha256sum lesos.img
```

Ожидаемый размер образа: **1474560 байт** (2880 секторов по 512).

Проверка сигнатуры загрузочного сектора:

```bash
xxd -s 510 -l 2 -p boot.bin     # должно быть 55aa
wc -c kernel.bin                 # должно быть ≤ 16384
```

Если вы используете LesOS в окружении, где важна целостность, соберите образ локально и сверяйте хеш с локально сохранённым значением. Публичных подписей и контрольных сумм не публикуется.

## Рекомендации по безопасному использованию

1. Запускайте LesOS только в QEMU или на изолированной виртуальной машине.
2. Не подключайте образ к реальным дискам: загрузчик работает в защищённом режиме и пишет в VGA/serial без ограничений.
3. Не записывайте образ на реальные дискеты для работы с важными данными.
4. Ограничивайте сетевой доступ виртуальной машины: драйверов сети в ядре нет, но проброс устройств (сеть, USB, буфер обмена) может обойти это ограничение.
5. Отключайте проброс буфера обмена и общих папок при запуске.
